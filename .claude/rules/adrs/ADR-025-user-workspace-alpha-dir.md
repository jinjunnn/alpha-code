## 背景

用户拍板(2026-07-09,REQ-071 登记连拍):产品在用户机器上的自有落点**全部是隐藏目录**(项目 `.alpha/` + 全局 `~/.alpha/` + userData),用户数据没有可见的默认工作目录。机制现状:无任何默认目录概念——开项目全靠原生选择器(`ipc.ts:130`,无 defaultPath 约定);无项目态的自动化/云任务产物没有落点起点(对非技术用户画像「登录即代付零配置」缺链)。

用户四点拍板 + 两点方向:① 创建时机 = **首次需要时**(lazy);② 无项目/未选项目时新会话**自动落 `~/Alpha`**(home 项目 chip 默认即它);③ 无项目态自动化/云任务产物**也默认落 `~/Alpha`**(补齐小白链路);④ 目录名**固定英文 `Alpha`**,不本地化不随品牌。并提出:目录内容要有规范(如按日期写入总结、用户记忆数据),明确**什么时机、什么数据、谁来写入**,以及是否需要 alpha 系统级 skill/agent 配合。

## 决策

1. **定位**:`~/Alpha` = alpha 的**用户可见默认工作目录**——普通目录、无项目态的默认项目。与 `.alpha` 体系**正交**(ADR-019 一字不动):`~/Alpha` 作为项目打开时,内部照常生成自己的项目级 `.alpha/`(harness 机器产物);`~/.alpha`(全局安装物/账本)与 userData(内部件)职责不变。心智口径:「`.alpha` 是 harness 的,`~/Alpha` 是你的文件」。
2. **供给 = lazy,主进程单点**:首次出现「无项目态要开会话 / 要落产物 / 打开目录选择器」时由 app 主进程创建(`mkdir -p`);不在 onboarding 抢跑、不迁移任何既有内容;`~/Alpha` 已存在(用户自建同名)则**如实沿用不覆盖不清理**。子目录同样按需建(用不到的不预建空壳)。
3. **默认接线**(拍板②③的实现面):
   - home 项目 chip:无项目/未选时默认显示并使用 `~/Alpha`,新会话零选择直接开始;**既有用户有项目照旧**(上次使用优先,不被改写);
   - 目录选择器:`open-directory-picker` 的 `defaultPath` 统一约定指向 `~/Alpha`(用户仍可任选);
   - 无项目态自动化/云任务:目标项目 = `~/Alpha`(run 机器产物照旧落 `~/Alpha/.alpha/runs/`,ADR-019/022 语义原样)。
4. **目录内容契约(用户可见区)**——只约束 **alpha 自动写入物**的落点与命名,用户自由放置的内容不清理、不接管、不重排:
   | 子目录 | 内容 | 命名 |
   |---|---|---|
   | `Journal/` | 按日期的总结(会话/工作日总结) | `YYYY-MM-DD.md`,同日追加不覆盖 |
   | `Memory/` | 用户记忆数据(agent 长期记忆,markdown,用户可读可编辑可删) | 一事一文件 + 索引,形态随记忆能力 REQ 定稿 |
   | `Outputs/` | 无项目态云任务/自动化的**用户可读交付物**(report 等可见件) | `YYYY-MM-DD-<slug>/`;机器产物(contract/status/账本)照旧留 `.alpha/runs/`,不重复不上移 |
5. **写入者矩阵(谁写 / 什么时机 / 写什么)**:
   | 写入者 | 时机 | 写什么 | 治理 |
   |---|---|---|---|
   | app 主进程 | 首次需要 | 只供给目录本体,**不写内容** | 单点供给,幂等 |
   | 会话内 agent | 用户对话中 | 用户要求产出的文件(cwd=`~/Alpha` 普通项目语义) | 既有权限体系,无特例 |
   | **系统级出厂 skill**(新增,本 ADR 拍板「需要」) | agent 写总结/记忆时 | 教目录契约:写哪、按日期命名、格式 | 经 config `skills.paths` 注入随包资源(REQ-065 纯度:出厂件不落 `.alpha`);**行为约定非硬约束**,诚实标注 |
   | 自动化(ADR-022) | 用户显式开启后按计划 | 预置「每日总结」自动化模板 → `Journal/YYYY-MM-DD.md` | **默认不开**(token 成本 + 写盘都要显式同意);standard 档,execution:local |
   | 云任务回流 | run 完成 | 交付物可见副本 → `Outputs/` | ⚠️ 回流写盘守卫(`alpha-workdir`,ADR-021 §5)现困在 `.alpha/` —— 可见副本通道需**受控扩展白名单**(仅 `~/Alpha/Outputs/`,消毒/体积帽同款),随实现设计 |
6. **治理边界**:alpha 自动写入只追加、不删改用户文件;总结/记忆写入各有用户可见开关;不做 iCloud/同步/备份;记忆**能力本体**(跨会话读写机制、注入通道)不在本 ADR——本 ADR 只钉落点契约,能力另立 REQ。

## 拍板(用户,2026-07-09 同日 —— 三残点全清,本 ADR 转 accepted)

1. **子目录命名 = 英文** `Journal/Memory/Outputs`(与根 `Alpha` 一致、路径稳、同步工具/agent 无坑;中文亲和留给 UI 展示层,不落文件系统);
2. **云任务可见副本归 T2**(alpha-workdir 白名单受控扩展随 T2 设计,T1 只做基础供给);
3. **总结触发 = 自动化模板 + skill 约定**,不做专门 UI 入口(会话内显式触发由 skill 天然覆盖:用户说「总结今天」→ agent 按约定落 `Journal/`)。

**配套拍板 —— 新增内置出厂技能 `alpha-workspace`**(命名可实现时微调):教 `~/Alpha` 目录契约(Journal 按日期追加 / Memory 一事一文件+索引 / Outputs 交付物语义),随包资源 + config `skills.paths` 注入(REQ-065 纯度通道,不落 `.alpha`)。**全局注入 → 「每日总结」自动化拉起的会话同样可用**:模板 prompt 只引用约定、不重复维护落点规则(一处约定,会话/自动化两处生效)。与既有出厂件职责不重叠(skill-creator/agent-creator 教造扩展、customize-alpha 教引擎配置、integrate-project 管外来导入;本件专职**用户数据写入约定**)。

## 后果

- ✅ 小白零选择开始(chip/选择器/自动化三处默认接线);用户数据有可见的家;总结/记忆有规范落点,不再散落隐藏目录。
- ✅ 复用面全部现成:lazy mkdir(主进程)、出厂 skill 通道(REQ-065)、自动化模板(ADR-022 standard 档)、回流守卫模式(ADR-021)——净新增 = 默认接线 + 一个 skill + 白名单受控扩展。
- ⚠️ 新增一个**可见写入面**:约定对会话 agent 是 skill 软约束(可能不遵守),硬保证只对自动化/回流产物成立——诚实分层,不装硬。
- ⚠️ `~/Alpha` 被用户改名/删除后 lazy 供给会重建空目录(数据不找回);属预期,文档明示。
- 🔭 执行载体 [[REQ-071]](T1 基础供给 / T2 契约配套);记忆能力本体后续单独立项。

## 修订(2026-07-19,[[ADR-031]] —— §6 治理边界的两条结论被窄修订)

[[ADR-031]](混合用户记忆,`proposed`)窄修订本 ADR §6 的**两条**结论。两条都只在 Memory 面生效,`Journal/`、`Outputs/` 与 `~/Alpha` 其余部分**完全不受影响**。

**① 「不做 iCloud/同步/备份」→ Memory 面允许用户显式发起的选择性云发布。**

原条款作用域是整个 `~/Alpha` 可见区。ADR-031 只取其中属于 Memory 的部分,允许用户把**明确选择**的条目或 scope 发布为版本化云快照。仍然不做:iCloud、整个 `~/Alpha` 的通用同步/备份、`Journal/`/`Outputs/` 的同步、实时双向文件同步、后台自动合并、静默 last-write-wins。

**② 「alpha 自动写入只追加、不删改用户文件」→ 拆为两段。**

- **自动写入仍只追加**。任何自动化、云回流、agent 后台行为都不得删改用户文件——这一条**未被削弱**。
- **新增:用户显式请求且指明范围时,产品可删除 Memory 文件**。owner 2026-07-19 裁决:「忘记」是记忆产品的基本功能,没有它用户无法收回已记内容。约束:必须由用户明确发起、必须指明目标范围(单条 / 一个 scope / 全部),不得由模型、自动化或云端状态触发;删除范围不得溢出 `~/Alpha/Memory/`。

> **本段的存在即是修订记录本身。** ADR-031 初稿仅声明修订了第 ① 条,§6 却同时建立了本地删除通道——该不自洽已由 2026-07-19 的跨仓审查发现并经 owner 裁决,ADR-031 的范围声明已同步更正为两条。
>
> Memory 文件的具体形态(§4 表格的「一事一文件 + 索引」)是否仍然有效,随跨仓 Memory 合同由 [alpha-platform#84](https://github.com/jinjunnn/alpha-platform/issues/84) 一并裁决;在该裁决落地前,§4 约定继续有效。
