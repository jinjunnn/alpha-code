> **状态:accepted(用户拍板,2026-07-12 同日)。** 起草于 2026-07-12 产品所有权专项(REQ-084~107)评审;用户已确认方向(「alpha 拿到更多主权、更深定制化」),本 ADR 是对「是否把 0 改上游修订为必要时可最小量改动」之问的正式回答形态。

## 背景

1. **用户方向(2026-07-12 确认)**:alpha 拿到更多主权、可更深定制化;产品所有权专项(REQ-084~107,见 [GitHub Issues](https://github.com/jinjunnn/alpha-code/issues) 与 [Alpha Delivery](https://github.com/users/jinjunnn/projects/2) 索引)是该方向的执行图。随之提出:是否把硬约束「只新增文件、绝不改 opencode 既有文件」修订为「必要时可最小量改动上游,但必须堵上更新冲突的口子」。
2. **技术事实一:「改一个仍在同步的文件且不冲突」不存在第三种实现。** 一个仍在每日 sync 的文件,任何本地改动都会在上游下次触碰时产生 merge 冲突;已知的两种堵法只有 ① **补丁**(磁盘保持上游原样,构建/恢复时机械施加,失效 loud-fail)与 ② **冻结**(文件退出同步集,冲突在定义上不可能)。「允许直接编辑同步中的文件」与「堵上冲突口子」逻辑互斥。
3. **技术事实二:两种堵法在宪法中都已有枚举先例。** [[ADR-004]] allowlist 已为 `/api/*` 路由预留 `patches/` 通道(loud-fail 纪律)、并枚举 `bun.lock` 结构性例外;[[ADR-020]] 已为前端走通冻结接管(`packages/{app,ui}` 退出同步、守卫范围修订、受控 re-freeze 为唯一写通道);[[ADR-007]]/[[ADR-008]]/[[ADR-015]] 路线A 已走通 build-time/运行时变换(磁盘一字节不动)。用户想要的「缺口」以**枚举例外**而非**自由裁量**的形式一直存在。
4. **技术事实三:当前专项没有修宪客户。** 逐条核查 REQ-084~107(2026-07-12):路由链写的是**冻结包**(经 re-freeze 机制,已在 ADR-020 射程内);artifact 链、扩展 v2 链、browser 全部为 alpha 自有代码;**无一项需要编辑仍在同步的引擎文件**(core/server/opencode/sdk)。
5. **风险认定**:自由裁量式「必要时可改」会把北极星「upstream sync 后冲突文件数 = 0」从机械可验证降级为主观判断,且让未来每个实现决策更容易给自己找「必要」;这套纪律得以长期成立,正因例外是**逐条枚举**的。

## 决策

1. **铁律条文不变**:NON_GOALS#1/#3 与 ARCHITECTURE 硬约束①「只新增文件、绝不编辑同步中的上游文件」维持原样;北极星「冲突文件数 = 0」维持机械可验证语义。
2. **立四级主权阶梯**。任何「alpha 要更深接管某上游行为/表面」的诉求,按**最低够用级别**落位;每一级都保持冲突数 = 0:

   | 级 | 名称 | 形态 | 冲突为何为 0 | 既有先例 |
   |---|---|---|---|---|
   | **L0** | 接缝叠加(默认) | 只增不改:plugin/tool/MCP/sidecar(main-IPC)/config 注入/alpha 自有包 | 不触碰上游文件 | ADR-002/005/019 全体 |
   | **L1** | 变换层 | build-time 或运行时 transform,磁盘一字节不动 | 改的是产物/内存,不是源码 | brand-i18n(ADR-007)、`patch-upstream.ts`(ADR-008)、prompt 转写(ADR-015 路线A) |
   | **L2** | 补丁层 | 磁盘保持上游原样,构建/恢复时机械施加 patch;**失效必须 loud-fail 阻断,禁止 warning 后继续** | git-tracked 源码恒等于上游 | ADR-004 为 `/api/*` 预留的 `patches/` 通道 |
   | **L3** | 冻结接管 | 文件/包退出同步集,alpha 取得完全所有权,**同时放弃该范围的上游白嫖**;唯一写操作 = 受控 re-freeze | 不再 merge,无处冲突 | 前端冻结(ADR-020) |

   **不存在 L4「直接编辑同步中的文件」——永不设立**(见背景 §2,它与目标互斥,不是保守是逻辑)。
3. **升级流程(逐案 ADR,不设通用许可)**:诉求方先给出**低级别不可行的勘探证据**(接缝/变换试过或论证过为何不够),再经一条 ADR 把**具体文件/包**挪上目标级别。该 ADR 必须载明:触发需求、级别选择理由、守卫/tripwire 形态、回退方案、(L3)放弃白嫖的范围声明。
4. **守卫映射**:L0/L1 = 北极星 file-diff 守卫既有覆盖,零动作;L2 = patch 施加步进 CI 且 loud-fail(施加失败即红);L3 = `alpha-ci.yml` 守卫 allowlist/范围修订(ADR-020 §3 先例)。北极星指标本身在任何级别下都不改写。
5. **既有例外向阶梯归位(记账,不改任何行为)**:`bun.lock`(结构性,ADR-004)≈ L2 特例;brand-i18n / patch-upstream.ts / prompt 转写 = L1;`patches/` 预留 = L2;前端冻结 = L3。此后新例外一律引用本 ADR 级别编号,不再各自发明表述。
6. **首个预期用例**:[[REQ-084]] 的冻结同步存活契约——「新冻结基点」= 行使 L3 既有 re-freeze 通道(机制零新增),「恢复后机械 seam patch」= 新增一台 L2 机器。本 ADR 立场:**预倾向前者**(已记入 REQ-084 档与 owning Issue #199,最终在 ADR-027 门内定)。

## 后果

- ✅ 「alpha 拿更多主权」获得正式、可审计的升级通道:每深一层是一条 ADR,不再每次重吵「要不要破例」;方向(主权)与纪律(冲突=0)解耦。
- ✅ 「必要时最小量改上游 + 堵住冲突口」的真实诉求被 L2/L3 完整承接,且比"允许直接改"更强——堵口方式是机制保证的,不靠实现者自觉。
- ✅ 北极星机械可验证性、CI 守卫形态、NON_GOALS 文字全部不动;本 ADR 是系统化而非放宽。
- ⚠️ L2 每条 patch 是持续维护面(上游漂移 → loud-fail → 修 patch),故 L2 需逐文件枚举、能走 L1 不走 L2。
- ⚠️ L3 是单向门:进入即放弃该范围上游白嫖(安全修复也不再自动进入,re-freeze 是唯一吸收通道,ADR-020 已实证此代价)。
- ⚠️ NON_GOALS#1 中「唯一例外:`/api/*` 走 patches/」的旧表述,与本 ADR 的 L2 通用定义存在措辞差(语义兼容);下次 retro 时把 NON_GOALS/ARCHITECTURE 的例外表述统一改为引用本 ADR 级别编号。
