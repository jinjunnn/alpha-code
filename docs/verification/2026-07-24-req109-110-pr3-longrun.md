连续运行 60 分钟无人交互。时间线 run 20260724T064451(236 marks),摘录判据如下。

## 冷启动(A′ 宽限)

- t=0.2s `token_check expired:true` → 续期立即启动;t=0.5s `boot.grace outcome:refreshed`
  ——**宽限内快续期,单次 boot fork**(rotation 标记 outcome:pending 由 latch 与
  fork 时 generation 快照自然消解,未产生多余换血)。

## expiresAt 调度(T5,#529 AC1)

调度器按 10 分钟节律(15min TTL × 1/3 提前量)触发,60 分钟内 6 次续期全部 `refreshed`:
600.7s / 1200.7s / 1800.8s / 2400.9s / 3001.0s / 3601.2s —— 与设计值逐秒吻合;
`scheduler.arm` 13 次(startup/result/auth-change 重排)。

## token-only 换血(T2+T4,#528 AC4 / #529 AC2)

每次续期 → **恰好一次** token-only 换血(generation 2→7):`recovering` 广播 →
respawn fork(~1s)→ `ready` 广播 → **`reload.skipped` ×6,整页 reload = 0**。
`root.mount` 全程 = 1(六次换血零页面重载);无任何 respawn 循环迹象
(60 分钟 6 次 respawn = 每续期一次,无多余)。运行中 sidecar 携带 stale token
的最长窗口 = 续期节律 10 分钟,远小于旧小时轮询下的数十分钟。

## 恢复信号消费(T3)

`renderer.sidecar.generation.received` ×13(与 emit 一一对应),
`retry_backoff.cancel` ×5(generation-ready 唤醒),换血窗口内 model.list
重试均以 ok 收敛(25 次 start / 25 次 end,19 次 retry_tick)。

## 观察项(如实):首次换血触发第四机制

首次 token-only 换血后 604.3s–632.6s 内 composer 子树 remount 6 次
(occurrence 2–7,~2s 间隔),此后 5 次换血 **零 remount**。root.mount 恒 1,
页面级判据(mount=1)成立;composer 级抖动即已上报 #528 的第四闪机制
(surface admission `resolvedSurfaces.latest` 迟到重收敛)——旧行为整页 reload
把它掩盖,免 reload 后首次换血将其暴露。归属裁定见 #528 评论,PR-3 按裁决
明确不碰 surface admission。
