沙箱开着的时候,把两件用户自己看不出原因的事说清楚

沙箱只允许终端和助手写入当前项目与 Alpha 自己的目录。由此用户会碰到两件事:终端里自己的配置有一部分静默失效;启动后才打开的项目写不进去,而失败只藏在某一次工具输出里。本稿在两处既有位置各加一句实话,不放宽任何东西,也不改任何行为。

取代无。「状态胶囊只有两态」那句仍成立:只读不是会话状态,是工作区状态,所以是另一枚胶囊而不是第三态。
为什么沙箱下这两件事今天零告知。用户看到的是「补全不灵」和「改不了文件」,会当成 Alpha 坏了。裁决是不放宽沙箱、不改终端行为,改为说实话 —— 那句实话就得有个固定的家。

终端:脚条里多一项「沙箱开启」,悬停说明哪些配置会不生效

脚条今天列的是环境事实:运行状态、shell、尺寸。「沙箱开启」是同一类事实,放在同一条里;它常驻、不可关闭、不弹窗 —— 与「zsh」「80×24」一样只是陈述。完整解释放在悬停层,因为脚条一行放不下,而需要它的人正是「补全怎么不灵了」那一刻会去看脚条的人。

元素解剖:脚条项 = 盾形小图标 + 一句话,胶囊描边、与脚条同一号 mono 小字、同一灰度;窄于 360px 时只留「沙箱开启」四个字,整句进悬停。悬停层 = 抬起的浅色卡(深色主题下同样是抬起的表面),标题一行 + 三句正文,箭头指回脚条项。
什么时候出现:只在沙箱真的装上时(引擎自报)。没装上的平台不出现这一项 —— 没有围栏就不说有。它不可关闭:与「zsh」一样是环境事实,不是通知。
空态那一行:同一句话的短版,放在「新建一个……」之下、按钮之上,三级灰。用户在开第一个终端之前就已经看过一次。
为什么不写进输出区:输出区归终端引擎,内容会被用户自己的 rc 输出冲走;脚条常驻,补全不灵的那一刻低头就能看到。

工作区:这个项目写不进去时,在项目层面说出来

沙箱允许写入的项目在启动那一刻就定下了。之后才打开的项目打得开、读得了,一写就失败,而失败只出现在某一次工具输出里。本稿把它提到项目层面:顶栏状态胶囊旁边一枚暖色「只读」胶囊,悬停 / 点击说明原因与出路;新对话页没有顶栏,同一信息落在工作区 chip 的尾标上。

同一信息chip 尾标与顶栏胶囊是同一个状态的两个宿主,悬停给同一段解释。选完目录、探针回报写不进去,尾标当场出现;进入会话后由顶栏胶囊接手。

状态什么时候呈现
探针未答目录刚成为当前工作区,真写一次的探针还没回来无标记。不预告、不闪现,答案回来之前什么都不说。
可写探针在该目录写入并删除成功无标记(今天的样子)。
只读被沙箱围住的引擎回报写入被拒胶囊 / 尾标出现,悬停 / 点击给解释;直到切换工作区或重新启动。
未知引擎不在、探针出错、或该平台没有沙箱无标记。未知不等于只读,不吓人。
元素解剖:胶囊 = 锁形小图标 + 「只读」两字,暖色淡底 + 暖色字,尺寸与状态胶囊完全同款、紧跟其后;悬停 / 点击弹层 = 抬起的卡,标题 + 三句正文 + 一行脚注 + 一个动作。chip 尾标 = 同色更小的一枚,嵌在目录名与折叠箭头之间。
为什么不是 toast:toast 会消失,而只读会持续到重启。用户需要的是回到这个项目时随时能看到的状态,不是一次性的提醒。
为什么不放左栏项目行:左栏列的是全部项目;只读描述的是「这个项目 vs 这次启动」的关系,只对当前工作区成立,所以挂在当前工作区的身份旁边。
判断只能靠真写一次(帧外):用路径字符串比较会在四种形状上出错(前缀相同但不是路径分段、软链进出集合、大小写不同的同一目录),所以标记只在被围住的引擎真的写失败之后才出现,而且探针必须先在可写项目上答过「可写」才算数。
「重新启动 Alpha」按钮(帧外):这是本稿里唯一超出「只呈现」的动作。没有它,弹层只告诉用户出路却让他自己去菜单里找;留着它是一个新动作。owner 可划掉 —— 划掉后弹层只留文字。
