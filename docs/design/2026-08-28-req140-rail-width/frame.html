会话工作区 · 右栏宽度规则增量 · 上限随窗口计算,会话列保下限

右栏可以拉到会话列让出的一切空间

右栏不再有固定的像素上限:能拉多宽,取决于窗口给了多少 —— 唯一的约束是会话列(时间线 + 输入框)保住自己的最小可用宽度。窗口越大,右栏可用的上限越高;窗口收窄时,右栏先让步,直到自己的下限为止。

规则 · 全部约束一张表

宽度契约

项值 / 规则说明
右栏最小宽320px沿用现行契约,不变。
右栏默认宽400px沿用,不变;宽度仍按面板分别记忆。
会话列最小可用宽480px新增。时间线 + 输入框所在列的下限;右栏拉宽永远不把它挤到 480 以下。
右栏上限会话工作区宽 − 480px新规则,取代固定上限。会话工作区 = 窗口除去左侧项目栏后的区域。无固定像素天花板。
两条约束冲突时右栏下限赢工作区不足 800px(320 + 480)时,右栏钉在 320px,会话列吃剩余空间 —— 右栏先让步,让完为止。
窗口变化实时按当下工作区宽收敛收窄:超出上限的右栏立刻缩回;拉宽:记忆宽度不超上限则完整恢复。
拖拽 / 键盘到达边界即停拖拽与 ←/→(步长 16px)在上下限处硬停,无回弹;拖动中左缘 2px 强调线常亮(沿用)。
记忆记用户选的宽按面板记忆沿用;读取时按当下上限收敛显示,记忆值本身不被窗口变化改写。

辅助技术合同:拖宽分隔条的 aria-valuemax 跟随当下的有效上限(动态值),不再是常量;aria-valuemin 恒为 320。

会话列 480px · 下限

面板内容随宽度铺满
(预览类内容最受益)

拖到上限:左缘强调线常亮,继续拖无位移。松手记忆当前宽度。

窄窗口(工作区 < 800px):右栏钉在 320px 下限,不再让步;会话列吃剩余空间,可能低于 480 —— 此时是窗口太小,不是右栏侵占。两个下限都到底后,再窄由窗口自身的最小宽度兜底。
不变的部分:tab 条、收起行为、按面板记忆、左缘 6px 拖宽热区与强调线、收起后时间线回中 —— 全部沿用现行形态,本稿只改上限规则。
