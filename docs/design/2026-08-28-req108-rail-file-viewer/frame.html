架构说明

本工作区分三层:renderer 承载界面,main 持有系统能力,引擎经本地接口提供会话与文件服务。

目录约定

  • 界面组件按面板分目录存放;
  • 共享契约集中在一处,双端各自消费;
  • 测试与实现同目录,夹具就近。

改动任何一层的公共接口,先更新契约,再改两端。

四种打不开,四种说法:过大(给节选 + 系统打开)、不安全(只说明,零动作 —— 不把可疑文件转交任何应用)、读取失败(可重试)、不支持(事实行 + 系统通道)。每一种都有原因行,不合并、不留白屏。
网页与 PDF 就地呈现:内容在查看器主体内的隔离内容区里渲染 —— 网页预览沿用既有隔离通道(无网络、外部资源全拦,拦截数如实显示在顶部状态行);PDF 用内置查看器,含页码缩略图与缩放。两者都不再新开独立窗口。

帧内数据均为演示值。隔离内容区(网页 / PDF)的骨架图为示意:实际内容由隔离通道渲染,查看器只画头部、状态行与容器边界。

入口与分流 · 一个查看器,三个入口

改动归审查,浏览归查看器

入口去向
文件树 · 无改动标的行查看器(本稿主体)
文件树 · 带改动标的行审查面板对应文件卡(沿用既定分流:改动优先看 diff)
时间线 · 写入/编辑文件卡审查面板(它是改动);审查文件卡头部提供「查看整份文件」动作 → 查看器
产物面板 · 预览列保持现有形态(它服务云端任务产物);其网页 / PDF 单元与查看器共用同一块隔离内容区语言

右栏内本地文件的预览面只有查看器这一块;审查看的是「变了什么」,查看器看的是「现在是什么」,产物面板看的是「任务产出了什么」—— 三者各自回答一个问题,互不重复。

帧外 · 交互与无障碍合同

交互契约

面合同
焦点进入查看器,焦点落在返回按钮;Esc 或返回 → 焦点回到树中来源行;从时间线入口来的,Esc 逐级返回(查看器 → 审查/树 → 时间线原行)。时间线滚动位置不因右栏开合改变。
模式切换预览 | 源码为 radiogroup,←/→ 切换;切换不重新读取文件(同一份已读内容两种呈现)。
读取终止取消按钮、切文件、切面板、收起右栏、切会话五条路都立即终止读取;终止后无残留进度条、无迟到内容闪现。
隔离内容区网页 / PDF 的内容区在查看器打开期间存在,关闭 / 切走即销毁(短生命周期);任何强模态(如权限确认)出现时内容区暂时隐藏,模态关闭后恢复 —— 模态永远不被内容区遮挡。
读屏状态切换(读取中 → 内容 / 失败)经 aria-live(polite)播报;四种失败态标题即播报文本;隔离状态行(「无网络访问 · 已拦下 N 项」)对读屏可达。
动效树 ↔ 查看器切换无滑动动画,直接切换(与面板开合合同一致);进度条动画 reduced-motion 下静止。
