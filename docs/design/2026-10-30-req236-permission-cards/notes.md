工具批准面板 owner 2026-10-10 已定为非模态、关不掉、停在输入框之上(§8.6 ③),照能力授权框的外壳画会让实现去改一个已批的面板。
所以外壳用面板自己的活稿,卡内的行样式用能力授权框的。

## 自查

- `grep -c Alpha frame.html` → `0`。小写 `alpha-ext-authz` / `alpha-ext-confirm` 只是取自能力授权框活稿的类名,不在可见文字里。
- 未改元素与活稿逐字对照(命令实跑):①「今天」那份菜单的三条 `menu-item` 与 `current/composer/design.html` 的 `tpl-perm` 逐字相同,只差哪一项带 `is-on`(稿里选中「请求审批」,与下面的权限按钮一致);②确认卡标题 `<h4>…允许这次操作吗?</h4>` 与主按钮 `<button class="pf-btn pri" type="button">允许一次</button>` 与 §8.6 ③ 逐字相同;③步骤行「运行 · 安装依赖」的标记与 §8.5 逐字相同;权限按钮 `chip perm` 与 composer 活稿逐字相同。
- 三份样式表都定义 `:root` token,按链接顺序 conversation-timeline 的值最后生效;能力授权框的行在深色下的边框色因此是 `#26272c`(它自己的表是 `#232428`)。这是 `docs/design/README.md`「token drift」一节登记过的已知分歧,本稿不处理。
- 本机用 headless Chrome 截了 1280 宽的浅色、深色两张整页图核对,没有启动 Code Puppy。

## 建议改 AC

1. **alpha-code#1575 AC1**:期限文字「应用或引擎重启后失效」改为「重启后失效」(「引擎」是工程词);「『将记住』逐字对应该请求的 `always`」改为「『将记住』与 `always` 一一对应(人话投影;原文由单测断言,不上卡)」—— owner 要求卡上不出现技术参数。
2. **alpha-code#1575 AC3**:「写明当前档位要求每次确认」改为「写明只能允许这一次的原因」,只读档写「只读模式下每次都要确认」。另:`askedBy:"ruleset"` 也可能来自用户自己写的权限规则而非只读档,那时这句不成立,建议补一条「非只读档时写『这个工具每次都要确认』」。
3. **alpha-code#1575 AC5**:委派卡披露行改为「子任务里不再逐项询问」;菜单「显示方案 §2.1 的边界说明」改为「显示批准稿的边界说明」(批准稿压缩了 §2.1 的句子,见文案出处)。
4. **alpha-code#1576 AC3**:三类标签改为「Code Puppy 内置」「Code Puppy 云」「第三方」。没有证明的一律落「第三方」,对用户来说「已验证」不增加信息;「来源」二字在标签位上是重复。
5. **alpha-code#1576 AC4**:补一句显示面 ——「步骤行尾只给不是『内置 · 本机』的步骤写位置;每一步的位置都在详情底部;旧记录里的内置步骤以列表底部一句『内置步骤位置未知』代替逐行」。否则「每个工具调用的执行位置……缺字段显示位置未知」可读成每行都要标。
