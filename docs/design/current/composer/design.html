首页对话页输入框 + 菜单模型选择供应商权限
Overview · 设计目标

一套输入框，三层模型，登录即解锁代理节点

首页与对话页共用同一个 composer(纯白、柔和阴影、克制图标);模型选择重做成三层 —— 代理节点(alpha-platform,登录解锁) · 国内直连(填 Key 即用) · 自定义节点(Base URL + Key + 自定义模型/等级/effort,即 OpenRouter 场景)。新增 effort 与 权限(完全访问/请求审批) 两个控件,均挂在 opencode 已有的真实接缝上。

顶部可切换四种账号态「会员 / 仅余额 / 余额不足 / 未登录」,实时观察代理节点的开放 / 软锁 / 硬锁差异,以及「浅色 / 深色」。所有颜色取自 alpha-ui/tokens.css 真值。

06 · 供应商接入

两条接入路径 · OpenRouter 的模型怎么管

左:国内厂商 —— 选厂商,只填 API Key,Base URL 由 alpha 托管。右:自定义节点 —— 填 Base URL + Key 后,在该端点下逐个添加模型,只需贴模型 ID(等级、是否支持 effort 按 ID 自动识别)。这正是 OpenRouter 的答案:一个 Key 挂 N 个模型 ID,全进输入框下拉;effort 不在这里设,运行时用输入框的 effort 控件调。

这里不设 effort —— effort 是运行时选择,改在输入框的 effort 控件;注册只记录该模型是否支持 effort(自动)。等级按模型 ID 自动识别、只读跟随模型;识别错了才点「调整」。
回答你的两个问题:① effort 不在这里配 —— 它是运行时、按任务变的选择,只在输入框的 effort 控件里调;注册表只自动记录「该模型是否支持 effort」。② 等级不用手填 —— 按模型 ID 自动识别(opus=旗舰、sonnet=高级、其它=标准),绑定该模型、只读;BYOK 自定义的等级只是标签(不计费,区别于代理节点)。③ 运行时只做两件事:输入框下拉换模型(等级随之带出)+ effort 控件换强度;一个 Key 配多次 = 多个模型 ID,全进「自定义」分组随点随切。
落地:写入用户 opencode.jsonc 的 provider["openrouter"] = { npm:"@ai-sdk/openai-compatible", options:{ baseURL, apiKey }, models:{…} }(与现有 alpha provider 同机制);每个自定义模型的 effort 写进其 variants。Key 入 keychain,只读注入。
07 · 权限

完全访问 / 请求审批 — opencode 已有引擎,新增开关

opencode 后端已有权限引擎:permission:"allow" = 完全访问,规则式 ask = 请求审批,配 permission.asked 事件与 once/always/reject 回应 —— 但没有界面开关。这里补上工具栏开关 + 审批卡片。

运行权限
完全访问允许全部
请求审批逐次询问
只读禁止写/执行
请求审批 · 工具执行
agent 想运行命令:rm -rf node_modules && bun install
映射:完全访问 → permission:"allow";请求审批 → 规则式 ask;按钮 → SDK permission.respond({response:"once|always|reject"})。开关写当前会话 / 项目配置。结论:能力真实存在,我们补的是 UI,不是造功能。
