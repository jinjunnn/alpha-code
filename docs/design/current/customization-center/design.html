评审点

Q1 推荐页严格化的过渡:未策展套件立即退出推荐?稿采用 A = 立即退出(推荐 = 纯甄选驱动,fail-closed;套件仍在套件 tab 全量可见,策展后自动回归推荐)。备选 B = 保留「套件」区块直到套件完成策展(体验平滑,但推荐页出现两套准入标准,「推荐但未审核」自相矛盾)。当前四个套件全部未策展,选 A 意味着推荐页短期没有套件区块。
Q2 类型 tab 内的分组轴?稿采用 A = 保留 category 分组 + 分级 chip + 「未分级」尾组(最小增量,货架身份不抢导航轴)。备选 B = tab 内按货架重组分区(治理轴更醒目,但连接器 tab 的用途分组被顶掉,且技能/插件 tab 从平铺变分组,IA 变动大)。
Q3 甄选能力面(fs:read 等)与授权账本(#348)的呈现关系?稿采用 A = 分置两段:甄选能力面进「数据边界」(审核观察,装前可见),授权账本留「已授权能力」(本地事实,装后出现),互不合并(F8:两本账,词汇与语义都不同)。备选 B = 详情页只展示授权账本、甄选能力面仅进安装确认框(更简,但装前用户看不到能力面,削弱「装前看清代价」)。
Q4 归档条目在浏览面的去留?稿采用 A = 如实展示 + 禁新安装(置灰按钮 + 归档 chip + 详情警示;与 REQ-105 已装归档处置同一诚实原则)。备选 B = 从浏览面隐藏(列表更「干净」,但已装用户找不到详情入口,且「悄悄下架」违背如实呈现)。
Q5 组件清单/来源快照的拉取时机?稿采用 A = 进详情页即拉取摘要行所需内容,校验通过才渲染(打开详情 = 契约允许的拉取时点;两个 blob 合计通常 < 1 KB,首屏即见校验态)。备选 B = 点「展开」才拉取(更省流量,但摘要行的「已校验 ✓」在点开前无法如实显示,只能显示「未获取」)。
硬约束(契约语义,不接受反转):货架 = tier 一一对应,消费端不得改判;启用策略只读 activationPolicy,绝不从 tier/type 推导;advisory/撤销永远赢过甄选字段;甄选摘要是展示真源,不重算替换;blob 拉取失败不影响货架与启用判定但必须如实报错;未知 schema/未知键/校验失败 = fail-closed 整体不采信 + 如实上报;复审过期 = 停止推荐 + 新启用显式确认;核心货架空则隐藏,不预造条目。
