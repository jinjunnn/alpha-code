启用与生效:装完不等于能用,这件事必须说出来

本地扩展包装完之后默认全部关闭。这意味着:如果界面不主动引导,用户按完确认会觉得「什么都没发生」,然后判定这个功能坏了。所以确认成功之后界面自动切到已安装页并把新包定位在最上面,包卡上带一行引导;开关拨开的那一刻引擎当场重载,下一条消息里技能就在。

评审点

Q1 包里的技能,要不要照常出现在下面的「已安装 · 全局」清单里?稿采 A = 照常出现 + 一枚「属于扩展包 X」的标。理由:①这是今天的行为,不做任何事就是这样,收起来反而是额外改动;②搜索、逐个启停这些既有能力不该因为进了包就消失;③用户在这里点垃圾桶,是「单个不能单独移除」那句拒绝唯一说得出口的地方(帧 8 态三)。代价 = 同一个技能在页面上出现两次、有两个开关(翻的是同一个状态)。备选 B = 收进包卡内不重复,列表更干净,但拒绝路径从界面上就到不了了。
Q2 「扩展包」区块只列本地导入的包,还是所有包?稿采 A = 账本里有什么就列什么(目录来的包也列,用「来自本地文件夹 / 来自官方目录」两枚标区分;目录包多一个「查看详情」入口通向已有的详情页)。理由:目录来的包今天在已安装页同样是隐身的,这个区块本来就是在补这个洞。备选 B = 只列本地导入的,增量更小,但已安装页继续对目录包撒谎。
Q3 一个都装不上时,确认键是禁用还是换成「知道了」?稿采 A = 保留确认键但禁用,并把原因写在键面上(「没有可安装的技能」)。理由:这一屏和能装的那一屏是同一屏,用户的心智模型不该在这里分叉。备选 B = 换成单键「知道了」,更像提示框,但会让「装不上」看起来像一次错误弹窗而不是一次说明。
Q4 预览用弹窗还是整页?稿采 A = 弹窗(继承导入 Agent 的两段式形状,尺寸放大到 lg,内容区滚动)。单插件技能数实测最多 13 个,弹窗装得下。备选 B = 整页,长清单更舒服,但要新开一条页面路由,而且会让「确认之前不写盘」这件事更难被看清。
Q5 确认成功之后跳不跳页?稿采 A = 自动切到已安装页并把新包定位在最上面。理由直接对着裁决:既然默认全关,不跳页的结果就是用户按完确认什么都看不到,然后认为功能坏了。备选 B = 留在导入页 + 一个 toast,改动更小,但把「装完像没装」这个已知风险原样留给用户。
Q6 包卡里的引导条什么时候消失?稿采 A = 这个包里只要有任意一个技能被启用过,就不再出现。备选 B = 用户手动关掉。A 更省事,但代价是:如果用户先开后关,引导条不会回来。
硬约束(不接受反转):①导入页不新增第六张卡,非插件目录的行为逐字不变;②每一条「不装」都必须带具名原因,没有「其他」这一档;③装完默认全关是产品裁决,界面不得「贴心地」自动打开任何一个;④移除失败必须显示失败,只有明确成功才算成功;⑤包内单个技能的移除请求 = 明确拒绝 + 指向整包移除,不是假成功;⑥取消 = 零写入;⑦「读不出清单」不许显示成「没有安装」;⑧本地文件夹的内容没有经过审核这件事,必须在按确认之前可见,不得写成「已验证 / 已检查 / 安全」。
