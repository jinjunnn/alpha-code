| 前提 | 复核手段 | 读数 |
| --- | --- | --- |

## 1. 问题的形状

出网授权今天有两个半场(`network-egress-derived.ts:187-193`):

- **静态半场** = 应用自己总会去连的常量(`network-egress-registry.ts`);
- **动态半场** = 从**围栏外的真源**派生的目的地(`#1379` 注入面 provider 表、`#1381` `mcp-servers/<env>.json`)。

两个半场共用一条规则:**一个目的地能进放行集合,当且仅当它有一个围栏外的真源。**
`#1414` 把这条规则推到全表后,分界不是「资源由不由模型生成」(文件路径也由模型生成),
而是**这条轴有没有真源、越界时有没有出口**:

| 轴 | 真源 | 越界时的出口 |
| --- | --- | --- |
| 文件路径 | 工作区并集 `fence-workspaces/<env>.json` | 有 —— `external_directory` 审批 / 把目录加进工作区 |
| 模型 API / 远程 MCP 目的地 | provider 表 / `mcp-servers/<env>.json` | 有 —— 在应用里添加那一家 |
| **`webfetch` 的 URL** | **无** | **无** |
| **`bash` 里命令自带的目的地** | **无** | **无** |

所以缺的不是几行白名单,是**这两条轴连「出口」都没有**:用户想让它过也没有任何地方可以表态。
本基线补的就是那个出口,以及它写下的那份真源。

## 2. 选定方案:授权判据的**第三个半场 = 用户批准的目的地**

一句话:**把文件轴那个已经在跑的形状(有真源 + 有出口)原样搬到网络轴上。**

1. **真源**:`<casBaseRoot>/egress-grants/<env>.json`,与 `mcp-servers/` / `custom-providers/` /
   `fence-workspaces/` 同父目录 —— **不在 seatbelt 可写集的任何一行之下**,只有 main 写。
2. **判据**:`isEgressAuthorizedForSidecar` = 静态表 ∪ 本代配置派生 ∪ **用户批准**。
   仍然只有这一处回答「这个目的地授权了吗」,仍然精确 `host:port`,仍然 fail-closed。
3. **出口**:代理在判出 `unregistered` 的那一刻,**先问用户**(main 进程的原生对话框,
   围栏之外),再决定 403 还是建隧道。用户勾「记住」才落进真源;不勾就只活在本次运行。
4. **两条轴用同一个机制**,因为它们在代理眼里是同一件事:一条 `CONNECT host:port`。
   `webfetch` 不需要任何改动 —— 它撞的就是这道判定;`bash` 里的 `curl` / `pip` / `git clone`
   同理。**不为 `webfetch` 单开一条通道**(理由见 §3 的「B」与「E」)。

### 2.1 为什么问的是「目的地」而不是「这次调用」

代理看到的是 TCP,没有可信的调用方身份:围栏内是同一棵树,`bash` 的子进程、MCP stdio、
仓库自带 plugin 与引擎本体在 loopback 上完全同形。所以**能够被批准的最小单位就是目的地**。
这一点必须写进文案与本文:**批准一个目的地 = 把它交给整棵树**,不是「只给 webfetch」。

## 3. 被否决的替代

| | 替代 | 否决理由(带坐标) |
| --- | --- | --- |
| A | 把目的地补进静态表 / 动态半场 | 结构上无解:`webfetch` 的目的地来自 `params.url`(`packages/opencode/src/tool/webfetch.ts:39-41`),`bash` 的来自命令字符串,两者都**没有配置来源**;匹配语义写死精确 `host:port`、不做通配(`network-egress-registry.ts:42-45`)⇒ 补完这五个,第六个照样 403 |
| B | 按调用来源放行(票面方向 3) | 一条 CONNECT 建的是**裸双向管道**,危险的是形状不是调用方;而且 loopback TCP 上拿不到可信身份,围栏内任何代码都能发出一模一样的 CONNECT。任何「只有 webfetch 能用」的实现都是假话 |
| C | 每次抓取当场问用户,但**不落真源**(票面方向 2 的字面读法) | 一次点击换一次连接 ⇒ 模型读五个链接问五次,同一个站点问无数次。本方案取它的「问」,但把答案写进真源,于是**同一目的地只问一次** |
| D | 关掉工具、承认不支持(票面方向 4) | owner 2026-09-23 已裁决:本地工具(含 web search / web fetch)必须能用 |
| E | 让 `webfetch` 改走 main 侧的取回服务(GET broker,票面方向 1) | ①它只救 `webfetch`,对 `bash` 一格都不救(`curl` / `npm` / `git` 说的不是 HTTP GET);②它在围栏上开第二个洞,而那个洞**同样**对整棵树开放(所有进程共享那一个可达端口),安全上不比目的地批准强;③它把「取回网页」这件事从引擎搬进 main,引擎侧 5 MB 上限 / 格式转换 / 图片附件(`webfetch.ts:96-124`)整套要在 main 重做一遍。参考实现在 `alpha-platform/packages/gateway/src/lib/web.ts`(带 SSRF 闸、14 处断言、**零消费者**)—— 它是**云 Worker** 的形态,那里 fetch 天然没有本机与内网位置,桌面端 main 有,照搬等于把 SSRF 面从围栏内搬到围栏外 |
| F | 复用引擎的 `webfetch` 权限批准(用户在时间线里点的那一下)去派生放行 | **两个值两个来源,可以分叉**:权限请求里的 URL 是引擎给的(`ctx.ask` 的 `patterns`),代理看到的 authority 是实际连接的那一个,中间没有任何东西保证它们相等 —— 一个恶意 plugin 可以就 `https://docs.example.com` 请求权限而实际连别处。让围栏外的判据去信一个围栏内产生的值,正是 `#1380` R1 Blocker(配置文件不算数)那条已付过学费的错 |
| G | 干脆放开:非私网的公网目的地一律放行 | 那是把 `#1073`/`#1336`/`#1337`/`#1379`/`#1381` 五张票买下来的性质退回原点 —— 围栏的全部价值就是「围栏内的代码不能把字节送到它自己挑的地方」。**不动**也一样定价:两条轴继续整类不可用,而 owner 已经裁决它们必须可用 |
| H | 对隧道做 MITM / 注入 CA 以便按内容判 | 2026-08-25 勘破 §4.2 已裁(不看隧道内容、不注入证书);它会让我们能读用户的全部流量,姿态比现在更坏 |

## 4. 反问:能否让本系统成为权威、让外部无从覆盖

- **权威在哪**:一条目的地进入放行集合,**当且仅当** main 进程里那个对话框收到过一次「允许」。
  没有第二条路径 —— 没有 env 开关、没有配置键、没有 CLI 参数、没有「散文说可以」。
- **外部能不能覆盖**:
  - **围栏内的代码**:真源文件在 `<casBaseRoot>/egress-grants/` 之下,而可写集的固定行
    (`process-fence-profile.ts` 的 W1–W19)没有一行罩得住它(判据:与 `#1381` 同形的逐行枚举测试);
    写端模块**不进 sidecar 的 import 闭包**(判据:`process-fence-write-sites` 的 `sidecarSourceFiles`)。
    ⇒ 引擎树改不了自己的放行集合。
  - **配置文件**:`alpha.jsonc` / `~/.opencode` / `XDG_CONFIG_HOME` 全在可写集里,因此
    **一个字都不读**(逐字沿用 `network-egress-derived.ts:20-32` 的裁决)。
  - **用户自己**:可以批准,这正是出口;但批准的**形状**由我们定(见 §5 准入),用户批不出
    loopback、批不出私网字面量、批不出畸形 host。
- **降级方向**:批准通道不在、无窗口、超时、并发超限、答「拒绝」—— **全部落到今天那条 403
  `unregistered`**,一个字节都不放。没有任何一条降级路径的方向是 fail-open。

## 5. 安全面:整类边界 + 实现必须守住的不变量

### 5.1 类边界(前置枚举,不留给逐实例修)

| # | 类 | 边界在哪 |
| --- | --- | --- |
| K1 | **谁能用一条批准** | 整棵围栏内进程树。代理按目的地放行,不按调用方 —— loopback TCP 上没有可信身份,同一棵树里也没有意义。**文案不得暗示「只给某个工具」** |
| K2 | **一条批准的带宽形状** | CONNECT = 裸双向管道。批准 = 交出一条到该目的地的**双向**通道(可 POST 任意字节)。**不得声称「只是读网页」** |
| K3 | **本机目的地** | 结构上到不了(§0 实测 N1):`NO_PROXY` 含三个 loopback 名,seatbelt N4 只放行代理端口。准入仍显式拒 loopback —— 否则登记簿会写下一句做不到的话 |
| K4 | **内网 / 元数据地址** | 私网、链路本地(含 `169.254.169.254`)、CGNAT、组播、保留 —— 这些**作为 IPv4 字面量**在准入处拒。**名字解析到私网 IP 不判**:与已发布基线「不做 IP↔名字等价、fake-IP 拓扑下按 IP 授权结构上无意义」(`network-egress-registry.ts` 匹配语义段)同口径。列为已知残留,见 §7 |
| K5 | **提示注入把对话框当攻击面** | 框里**只显示目的地**,不显示任何模型产生的文案(否则模型能在系统框里写字);默认按钮 = 拒绝;`Esc` = 拒绝 |
| K6 | **弹框风暴 / DoS** | 同一目的地同时只问一次(合并);并发待答目的地封顶;超时即拒;无窗口立刻拒(不挂起);被拒与超时进**记忆**,一段时间内不再问 |
| K7 | **端口是键的一部分** | 与另外两个半场逐字相同:批准 `github.com:443` **不**批准 `github.com:22` |
| K8 | **明文 HTTP** | 代理只做 CONNECT(`network-egress-proxy.ts:162-169` 对非 CONNECT 一律 405)。批准对 `http://` 目标**不生效**,它仍然 405。本票不改这条 fail-closed 的语义,见 §7 |
| K9 | **三个半场只做并集** | 用户批准不能删除、覆盖、改写静态表或动态半场的任何一条 |
| K10 | **持久化边界** | 只有勾了「记住」才落盘;不勾只活在本次运行。落盘走与 `#1381` 同形的原子写,坏记录不落盘 |

### 5.2 不变量(实现必须守住,每条都有判据)

- **I1 单一判据**:仍然只有 `isEgressAuthorizedForSidecar` 回答「授权了吗」。代理不自持第二份清单。
- **I2 降级恒 fail-closed**:没接批准通道 / 无窗口 / 超时 / 超并发上限 / 用户拒绝 ⇒ 403 `unregistered`,
  与今天的字节逐字相同(拒绝正文、结构化记录、reason 都不变)。
- **I3 批准只能来自 main 的用户交互**:围栏内没有任何写入路径(真源在可写集外 + 写端不进 sidecar 闭包)。
- **I4 准入判据不抄第二份**:host 形状用静态表那个 `isEgressHostShape`,loopback 判据用同一个
  `isLoopbackHost`(本票把它从 `network-egress-derived.ts` 挪到 `network-egress-registry.ts`,
  两个消费者共用一份,不是复制)。
- **I5 匹配语义同源**:精确 `lowercase(host):port`,不通配、不后缀、不 IP↔名字等价。
- **I6 拒绝有记忆**:同一目的地被拒/超时后,记忆期内直接 403 不再弹框。
- **I7 答案与连接解耦**:客户端在等待期间断开**不取消**那一问;答案照样落账,下一次重试即可用
  (`webfetch` 默认 30 s 超时短于人类反应时间,这条让「第一次失败、再问一次就好」成立)。
- **I8 真源严格读**:缺失 = 没有批准过(正常,不出声);解析失败 / 版本不认 / 形状不对 ⇒
  「没问出来」+ 一行原因,**当作空集合**(不是放行),与 `#1387` 同口径。

## 7. 本方案明确不做的(已知残留,不是遗漏)

1. **`http://` 明文目标仍然不通**(K8)。代理只做 CONNECT;要支持明文得把它变成真正的转发代理,
   那是另一道安全面(可读可改用户流量),不在本票。
2. **名字解析到私网 IP 不判**(K4)。与已发布基线同口径;要改得先推翻「fake-IP 拓扑下按 IP 授权
   结构上无意义」那条勘破,而本机所有出网都经透明代理(fake-IP `198.18.x.x`),照 IP 立闸会**拒载真实配置**。
3. **对话框里没有「是谁要连」的上下文**。代理只看得见 TCP;引擎侧的调用上下文在围栏内产生,
   按 §3-F 不可作为授权依据。可以作为**展示**再接一条通道,但那是新的接缝,另票。
4. **撤销面只有「删那个文件」**。设置里的「已批准的目的地」列表与一键撤销未做,另票。
5. **`websearch` 的两个端点**(`mcp.exa.ai` / `search.parallel.ai`)不在本票。它们是源码常量、
   有真源,按 `#1414` §3 属于「补两行就好」的那一类,与本轴不同类。
