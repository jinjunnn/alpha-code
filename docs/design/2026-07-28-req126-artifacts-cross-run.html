与上一稿的关系

视觉血统:current/artifact-workbench/design.html(产物设计的现行权威,PAGE-MAP 指定) × 2026-07-24-session-seam-baseline.md(右栏四面板与宽度契约) × 2026-07-28-req126-shell-navigation-baseline.md §1.3 / S3(全页工作台下线的裁决与其明说的能力差额)。 本稿是这三者之上的一层状态增量:不新增页面、不新增覆盖层、不重排产物面板的信息架构。

原样继承

产物工作台的构件语言

  • 卡片行:文件名 + 状态 chip + 体积 + 警告计数,行距与圆角一字不改。
  • 状态 chip 六态与配色:已验证 / 未验证 / 校验不符 / 文件缺失 / 未登记 / 未下载。
  • 预览三页签「预览 · 源文 · 元数据」与其单渲染器崩溃隔离。
  • 「打开前复核」闸门:复核未过一律不出预览,失败诚实可重试。
原样继承

右栏形制

  • 右栏宽度契约 320–560,默认 400,左缘拖拽把手不动。
  • 顶部四面板胶囊条「审查 · 文件 · 终端 · 产物」不动。
  • 面板顶部允许有一条自己的条 —— 审查面板是摘要条,终端面板是页签条,文件面板是筛选条。产物面板本来是这四个里唯一没有的。
  • 时间线产物行 → 右栏定位、Esc 归位的联动不动。
本稿新增

三件,全部长在既有挂载点上

  • 云任务条:一个可展开的选择器,替掉现在那行写死的小标题。展开即这个项目的历次云任务。
  • 单件取回:把工作台早已有、右栏被砍掉的「未下载 → 下载 → 可预览」动作装回卡片行。
  • 新结果提示:云任务回流落盘后,条上出现一条可点的提示,不抢焦点、不自动跳。
不继承的一件:项目选择器。 下线的全页工作台顶部有一个「项目」下拉,可以跨项目看产物。右栏不恢复它 —— 右栏的项目由当前会话决定, 加回项目下拉等于把全页那条「与当前会话无关的工作面」偷偷搬进右栏,正是被裁掉的那个形态。

03

数据通道真相:哪些今天就有,哪些今天没有

本稿画的每一个可点的东西都必须能指到一条现存通道。下表是逐条勘破的结果 —— 凡是「今天没有」的,本稿不假装它有:要么不画,要么画成明确需要裁决的选项。

面板上的东西它读/写哪条通道今天有吗说明
历次云任务列表 runArtifacts.projectUsage(directory) → usage.runs[](main/artifact-service.ts:1615) 有 已在面板里被调用,只是只取了第 0 个。遍历 .alpha/runs/*,云端回流写的 run 与本地 run 同在此列。
某次云任务的产物清单 runArtifacts.list(directory, runId) 有 已在用,换个 runId 即可,零改动。
每行的「N 个产物 · 体积」「N 个缺失」 RunArtifactUsage 的 artifactCount / diskBytes / missingCount / readOnly(artifact-service.ts:1547-1559) 有 字段齐全,与下线的全页工作台那一列同源。
项目用量条 usage.totalDiskBytes / usage.limits.projectMaxBytes 有 同一次 projectUsage 调用即返回,不多一次 IPC。
「未下载」卡片(平台有、本地无) cloud.artifacts(runId) → deriveCards({..., cloudArtifacts}) 有 run 目录名就是平台的 job id,同一个字符串直接传。需登录 + 联网;失败返回 {error} 信封而非抛错,离线/未登录降级成「只显示本地」。
单件下载 / 进度 / 取消 cloud.downloadArtifact · cloud.onArtifactProgress · cloud.cancelArtifactDownload 有 字节不过 IPC,落盘后自动写回清单,状态随之从「未下载」变「已验证」。进度事件按 artifact id 到达。
整次云任务回流落盘 cloud.saveRun,由 CloudRunWatcher 在云任务终态时自动调用 有(且已自动) 关键澄清:回流本身早就自动发生并且真的下载字节。缺的从来不是「取回动作」,是「面板知道它发生了」。
回流落盘后通知界面 —— 没有 渲染进程没有任何「run 已保存」推送通道;watcher 落盘后只弹 toast。这是本稿唯一需要裁决的新通道(见「待裁决 A」)。
某次云任务的时间 —— 没有 RunArtifactUsage 全字段里没有任何时间。盘上其实有(artifacts.json 的 updatedAt),但 projectUsage 没把它带出来。见「待裁决 B」。
某次云任务的成败 —— 没有 回流会把完整状态写进 run 目录的 status.json,但没有任何 IPC 读它 —— 纯只写。所以行上不能出现「已完成 / 失败」。
某次云任务的标题 / 归属会话 —— 没有 清单里没有标题、没有会话 id、也没有「云 or 本地」的区分。行上唯一稳定的身份就是它自己的编号。
删除 / 清理某次云任务 —— 没有 产物 IPC 刻意无写面(preload/types.ts:897-898:保留策略未定前不暴露删除)。故「run 级管理动作」整体划出本稿范围。
一句话结论:「跨云任务浏览」和「单件取回」今天就能做,零新通道; 「落盘即刷新」需要一个新的推送通道或一次退让(见待裁决 A); 「行上显示时间」需要在现有结构上多带一个字段(见待裁决 B)。

07

云端取回:四态

先分清两件被混称的事。整次结果的回流是自动的、而且早就在跑 —— 云任务一结束就把状态与全部产物下载到本地。 这里的四态说的是单件补取:整次回流时某一件下载失败(回流对单件失败是降级不是中止)、 或本地文件后来消失了,平台那边还在,那就该能单独把它取回来。四态用的是下线的全页工作台里那台已经写好、已有测试的下载状态机。

单件取回状态机 确定 reducer;终态之后到达的进度帧一律丢弃

未取回

平台有、本地无,或本地文件已消失。卡片带「未下载 / 文件缺失」,行尾一枚「下载」。

→
取回中

百分比 + 「取消」。进度以 aria-live polite 播报,不打断。

→
已取回

落盘即写回清单,状态自动变「已验证」,预览随之可用。

失败 / 已取消

失败留在行上并可重试;取消回到未取回,不留错误痕迹。

10

交互契约

键盘与焦点

展开

条本身是一个展开按钮,回车/空格开合,展开时焦点进列表首行;Esc 收起并把焦点还给条。

列表内

上下键在行间移动,回车选定并收起 —— 与右栏其它列表同一套漫游焦点。

Esc 的两级

列表展开时 Esc 只收列表;收起状态下 Esc 才沿用现役行为,把焦点还给时间线上发起的那一行。

切换后的落点

换一次之后焦点留在条上,不跳进卡片列 —— 用户可能想连着再换一次。

下载播报

进度以 polite 播报,不打断当前朗读;完成与失败各播报一次终态。

新结果提示

提示条出现不移动焦点,仅以 polite 播报一次;它可被 Tab 到达。

状态迁移的呈现规则

换一次 = 换上下文

换一次即丢弃上一次的选中件、预览模式与核对结果,回到该次的第一件与「预览」页签。不跨次保留选中。

刷新是重取不是合并

刷新重取列表与清单;正在下载的件不被打断,其进度状态跨刷新存活。

失败不升级

核对失败、下载失败都停在自己那一格,不会因为别处成功而被抹掉,只有显式重试能改写。

11

待裁决

三项,都不阻塞切换器本身;A 与 B 影响面板能不能做到「结果一落地就看得见」和「行上有没有时间」。

A · 云任务结果落地后,面板怎么知道 需要裁决

今天没有任何「已保存」推送到界面。三条路,代价与诚实度不同。

A1
加一条最小推送通道

回流落盘成功后,主进程推一条只带项目目录与任务编号的事件;面板收到即显示提示条。一条通道、一个事件、零轮询,提示与事实严格同步。代价:新增一个 IPC 通道并登记。

A2
面板重新可见时自己重取

切回产物面板 / 窗口重新聚焦时重取一次。零新通道,但用户盯着面板不动时结果落地了也不会动 —— 提示条这个形态就得砍掉,退回「手动刷新按钮」一件。

A3
定时轮询

面板可见时每隔几秒重取。不推荐:反复走磁盘遍历,而且「几秒」是个凭空的数,依然不准。

B · 行上要不要有时间 需要裁决

本稿画的是没有时间的版本 —— 因为现有通道确实取不到。但时间其实已经在盘上。

B1
把已有的时间带出来

每次云任务的记录里本来就有一个更新时刻,只是没被带进项目统计。带出来之后,行上就能显示「今天 15:02」这类人能读的东西,排序也能从「按编号倒序」改成真正按时间。改动集中在一处结构与其填充,不新增 IPC。

B2
就按本稿画的来,只有编号

零改动、绝对诚实,但用户要靠编号认「哪一次是我要的那次」,并且排序永远只是近似按新旧。

C · 「记录不可读」这枚 chip 的措辞 建议直接采纳

现役文案是「manifest 只读」—— 内部词上了界面。本稿改为「记录不可读」。若 owner 另有偏好的说法,在这里定,一并改掉。

12

不做的

明确划在外面,免得实现时顺手长回去。

  • 全页产物页面不以任何形式回来 —— 不做新路由、不做覆盖层、不做「在新窗口打开」。产物只经会话右栏到达。
  • 项目选择器不进右栏。右栏的项目由当前会话决定。
  • 删除 / 清理某次云任务不做。产物通道刻意没有写面,保留策略未定前不暴露删除;这也意味着用量条只能看,不能在这里清。
  • 行上显示成败不做。回流写下的状态今天没有任何读取通道,画上去就是编的。
  • 跨次搜索 / 过滤产物不做。先把「能到达」解决,过滤是它之上的另一层。
  • 预览器本身一行不改。Office 结构检查、隔离 HTML 预览、快速查看各归各的交付。
  • 时间线产物行的联动不改。它今天指向的是当前展示的那一次,切换器落地后仍然如此。
  • 手动触发整次回流不做。回流由云任务终态自动发生;给用户一个「重新回流」按钮既无对应通道,也会让人以为结果需要手动抢救。
