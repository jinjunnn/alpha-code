## 背景(为什么)

2026-07-03 用户在 v0.1.0 桌面端截图反馈一批 UI 视觉问题,并强烈质疑「是不是回滚了,我之前做的视觉设计稿已经实现了,谁搞的」。

**根因判定(git 已核,非回滚)**:
- 全仓 `git log --all -i --grep="revert|rollback|回滚"` 查无任何 alpha-ui 的还原提交;查到的 "Revert" 全是上游 opencode(core/mcp/OpenTUI),**没有一条碰前端**。用户的设计工作**没有被 git 回滚**。
- 时间线:alpha-ui 全套 reskin(时间线 40 构件分区 / 模型选择器接管 / composer)在 **2026-06-27 ~ 06-30** 落地并当时核验(commits `631970b2`/`23f972f2`/`392efa39`/`de4f5bd7` 等)。
- **2026-07-02/07-03 落地 546-commit 上游同步**(merge `3b638e4a` 07-02 20:47、`22107dd5` 07-03 02:14),**晚于** reskin。
- alpha 前端接管是 **CSS-only reskin,钩上游 `data-slot`/`data-component`/`class` 选择器**(ADR-016 决策②、ADR-008 上游耦合点)。ADR-016 ⚠️ 明确警示:「上游重命名内部 hook/context → CSS 换肤**静默失效**」;这正是 **C14(升级静默破坏面,232 选择器)** 追踪的机制。

⟹ **主假设:546-sync 重命名/改动了部分被 reskin 依赖的 DOM 钩子与注入锚点,使一批换肤规则静默回落到上游默认样式、且部分触发点(trigger→dialog)接线错位**——外观上「像回滚了」,实为升级耦合面断裂。属北极星的已知代价(前端已放弃升级隔离,ADR-016),不是有人改坏。

**强证据(图8,2026-07-03 追加)**:用户点侧栏「搜索」弹出的竟是**那张完整的自有模型选择卡**(搜索模型/供应商 · PRO 会员额度 · 代理节点 经 ALPHA 代理 · 启用代理 · 旗舰/高级 tier ×8 badge)——即**已实现的设计稿组件仍在代码里、仍能渲染**,只是被绑到了错误的触发点(搜索),而搜索页自身反被顶掉。⟹ 修复方向 = **重新接线/修注入锚点**,不是重建组件。这与「没被 git 回滚」的核查结论一致。

**待复验**:build 第一步须做**选择器 diff 确认**(`git diff <old-dev>..<new-dev>` 上游相关组件的 data-slot/class),把「疑似」升为「确诊」,再逐项修;不排除个别项是 reskin 本身覆盖不全(如 user.css 从未如 assistant.css 完整)。

## 目标(做什么)

修复下列各项(图1–图9)视觉/注入/路由回归,恢复到 ADR-016 设计稿的自有质感与交互;并把断裂的耦合面按 [[C14]] 薄 re-export/集中选择器策略收敛,降低下次 sync 再断的概率。
