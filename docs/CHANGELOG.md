## [Unreleased]

### Added
- **@ 和 + 现在打开同一个"装配"弹窗;计划模式一键开启**(REQ-073,需下个签名版本生效)——输入 `@` 或点 `+`,同一个弹窗按节呈现:添加(文件和文件夹 / 附加终端 / **计划模式**)、Agent(@general/@explore 中文一句话简介 + 内置/个人标识)、文件(输入即搜)、扩展(一行直达扩展市场;此前"文档/PDF/表格/连接器"四行点谁都是同一动作,已收敛)。开启计划模式后输入框旁出现可关闭的「⊗ 计划」标签、提示语切换,发送自动走 plan 档(先出方案再动手);点标签、再选一次或按 Shift+Tab 都能关,新会话默认回 build。工具条上原来的「build」组件已移除——默认就是 build,不需要一个永远只有一行的下拉。记住分工:**`/` 执行,`@`/`+` 装配**(引用、附加、模式)。
- **键盘选中不再被鼠标"吸走"**(REQ-072/073 连带根治)——列表弹窗每次刷新时,若鼠标恰好悬停在弹窗上,浏览器会在原地合成一次鼠标事件把键盘选中拽回悬停行(表现为↑↓偶尔"失灵")。现在只有鼠标真移动才会改变选中。
- **`/` 命令菜单大修:键盘能用了、技能全都在、搜索真的搜**(REQ-072,需下个签名版本生效)——三处硬伤根治:↑↓ 键盘选择此前按了没反应(选中被内部刷新瞬间重置),现在可循环选择且滚动跟随;技能列表此前只显示前 12 条(排后面的技能永远看不见,得碰运气搜首字母),现在全量可见滚动可达;搜索此前只认命令名,现在名称与简介都搜(搜「审查」能找到 /review)、前缀命中排前、搜不到时如实显示「无匹配命令」而不是弹窗消失。展示随之重排:按类型分节(内置命令/技能/项目/MCP)+ 行首类型图标;来源改为行尾对齐的小字(内置/个人/项目/MCP,「个人」= 你自己装的,淡紫标识);出厂与内置命令简介转中文,第三方技能保留作者原文不机器翻译;底部常驻键位提示与「@ 引用 Agent / 文件」。新增 `/agents` 直达 Agent 管理;记住这个分工就够了:**`/` 执行,`@` 引用**。
- **新增默认工作目录 `~/Alpha`,不选项目也能直接开始**(REQ-071,需下个签名版本生效)——全新用户首页不再是「请先选择工作区」死点:未选项目时工作区默认落在个人目录下的 `Alpha` 文件夹(Finder 可见,首次真正使用时才创建;已有项目的用户不受影响,工作区菜单里也常驻「Alpha · 默认工作区」一键可切)。所有「选择目录」对话框默认定位到这里;自动化新建任务的目标目录也默认是它。已存在同名文件夹时如实沿用,绝不覆盖。
- **总结与记忆有了规范落点(Journal / Memory / Outputs)**(REQ-071,需下个签名版本生效)——新增出厂技能 **alpha-workspace**:会话里说「总结一下今天」「记住 X」,内容按约定写进 `Alpha/Journal/日期.md`(同日追加)与 `Alpha/Memory/`(一事一文件,可自己编辑);自动化面板新增「每日总结」模板(一键预填每天 21:00 写日报,保存与启用仍由你确认,默认不开);以 `~/Alpha` 为目标的云任务/自动化,其报告等交付物额外镜像到可见的 `Alpha/Outputs/日期-任务号/`(引擎内部记录仍在 `.alpha`,不重复展示)。

### Fixed
- **BYOK 智谱 GLM / MiniMax「测试通过、会话却没反应」根治**(REQ-074,需下个版本生效)——两层问题一并修:① 配置供应商时「测试连接」与真实会话此前走的是**两个不同的 URL**(测试打对了、会话打错了;智谱网关对错误路径返回 200 包错误体,界面与日志双双无报错,表现为发消息后毫无动静),现在测试与会话严格同一拼法(测试通过 = 会话能用);② 引擎对「目录声明的模型」与「从公共模型库合并进来的模型」(如 glm-5.1)走不同的协议栈,anthropic 兼容接入点只对前者成立——内置供应商全部改走各家 **OpenAI 兼容端点**(智谱 `…/api/paas/v4`、MiniMax 官方现行域名 `api.minimaxi.com/v1`,均实测可用;旧 `api.minimax.chat` 配置两条路全 404,之前测试也不可能通过),两类模型自此协议一致。DeepSeek / 通义 / Kimi 全量核查无恙。自定义「Anthropic 兼容」节点的表单现注明:Base URL 填到 `/v1` 结尾。
- **窗口收窄时输入框跟手缩放,不再溢出窗口被裁**(REQ-075,需下个版本生效)——审查面板开启(或开过)后,会话栏宽度是一个记忆值,窗口缩小时不重新计算:输入框连同模型选择按钮被推出窗口右缘(看得见一半、点不着),要一直缩到很窄才突然恢复。现在会话栏永不超过窗口可用宽度,缩放全程连续跟手;审查面板在空间不足时自动让位。
- **未登录不再默认选中「登录才可用」的代理模型**(REQ-069,需下个签名版本生效)——此前未登录启动,输入框可能默认(或沿用上次登录期的选择)停在会员专属代理模型上,发第一条消息就被「预授权拒绝: member-only model 需 active 会员」原文糊脸。现在启动时按序解析:上次使用的模型(先校验当前还能不能用)→ 登录且账户可用时的代理默认档 → 已配 KEY 的自带供应商 → 都没有则保持「选择模型」引导。登录期的选择在登出后**暂停而非删除**(选择器里如实说明原因,重新登录自动还原);即使状态漂移,发送前也会先行内引导(登录或换自己的 KEY 模型),不再把网关拒绝原文当第一道界面。
- **未登录时模型选择器不再逐条展示海外模型**(REQ-069,需下个签名版本生效)——GPT / Claude 等代理模型的具体型号此前未登录也全量列出(全部锁定、点了只能去登录,观感是一排点不了的墙)。现在未登录时代理区收敛为一张「登录后可用 GPT / Claude 等海外模型 · 零配置」引导卡,DeepSeek / 智谱 / 通义 / Kimi / MiniMax 等自带 KEY 的国内供应商照常显示可配。
- **网关与云任务接口切换到自有域名**(REQ-070,需下个签名版本生效)——模型代理与云任务的默认接入点从 `*.workers.dev` 迁移到 `*.tidelabs.click`(境内可达性显著更好;`workers.dev` 存在广泛的 DNS 污染/连接重置报告)。旧地址在迁移窗口内保持在线,已登录用户的接入点也会随下次登录自动刷新。

### Added
- **其它工具的目录内容不再未经确认进入模型上下文**(REQ-063,需下个签名版本生效)——此前打开任何项目,其自带的 `.claude/`、`.agents/` 技能与 `CLAUDE.md` 会被静默读入(陌生仓库的提示注入面);现在默认不读取。项目自带这类内容时首次打开会询问:「导入」= 转换为该项目 `.alpha` 下的原生扩展(快照,原文件不动,可卸载可溯源);「忽略」= 保持不可见,按项目记录一次不再重复问。存量用户升级后首次启动会一次性询问是否把 `~/.claude`/`~/.agents` 里的技能与全局指令导入为 alpha 原生(不导入则明示从此不可见,原文件保留);之后随时可在会话里说「导入外部技能」(新出厂技能 integrate-project)补做或刷新快照。逃生开关 `ALPHA_ECOSYSTEM_INHERIT=1` 整机恢复旧行为。——此前模型常自称「alpha code (opencode)」、并把你指向 opencode 官方文档和 GitHub 仓库(对 alpha-code 用户全部失实)。现在发给模型的系统提示词在运行时完成品牌转写(底座工程能力原样保留,只转自我指代;你项目里提到 opencode 的文件名、包名、路径等真实事物一概不动);`/init` 与 `/review` 两个内置命令的模板、常驻子 agent(general/explore)的指令内容也改由 alpha 自有文本承载。新增出厂技能 **customize-alpha**:会话里问「怎么定制」即可获得 `.alpha` 配置、连接器、技能、治理等完整指引。逃生开关 `ALPHA_PROMPT_REBRAND_DISABLE=1` 一键恢复原样。
- **斜杠菜单更干净、每条命令自报家门**(REQ-066)——在治理设置里禁用的技能不再出现在 `/` 菜单(此前带「(已禁用)」占位仍列出);解禁后无需重启,下次打开菜单即恢复。菜单每条命令新增来源徽标:`内置` / `技能` / `项目` / `MCP` / `导入`,一眼分清命令来路;手动键入已禁用命令全名仍会收到诚实的禁用说明,不会假装执行。
- **项目里的一切定制只住 `.alpha` 一个目录**(REQ-060,需下个签名版本生效)——在会话里创建的技能 / Agent / 命令 / 连接器 / 插件全部落到项目的 `.alpha/` 下,项目里**不再出现 `.opencode` 目录**;没用过扩展的项目连 `.alpha` 都不会出现。模型经新的注册工具写入(字段校验、原子写、自动生效),不再手改配置文件;写完当前回复结束后自动重载,下一条消息即可用,无需重启。配套:全局安装 Agent 也不再在 `~/.opencode` 留任何痕迹(「`.alpha` 是你的,`.opencode` 是引擎的」自此全兑现)。
- **打开自带可执行扩展的项目会先征得你同意**(REQ-060 信任门,需下个签名版本生效)——项目若自带连接器(MCP)或插件(均为可在本机运行的程序代码),首次打开该项目会话时弹窗列明具体条目,你可以选择「允许加载」(需勾选知情确认)或「仅文本扩展」;技能 / Agent / 命令等文本类扩展不受影响。决定按项目记录一次不再重复询问,同意后无需重启即刻生效;拒绝后该项目的可执行扩展保持不加载。项目里放置未打包的 TypeScript 插件会被如实拒载并在日志说明原因(桌面运行时无法执行,需先打包成自包含 JS)。

### Fixed
- **「打开项目…」选完目录直接切换工作区**(REQ-068,需下个签名版本生效)——此前首页工作区菜单里选「打开项目…」,目录选完界面毫无反应(工作区还停在原项目,新项目也不出现在列表里),等于进不了新项目。现在选完立即切换到所选目录,取消则保持原样。
- **`~/.alpha` 与配置文件里不再出现你没装过的东西**(REQ-065/REQ-067,需下个签名版本生效)——出厂内置的技能此前以链接放在 `~/.alpha/skills/`、路径和"出厂禁用"还以明文写进你的配置文件 `alpha.jsonc`(系统件混进用户领地)。现在全部内置化:`~/.alpha` 只存放**你自己**安装/创建/导入的内容,配置文件只记录**你自己的**连接器/技能/Agent 和你的治理决定;出厂技能与出厂禁用项由 app 启动时在内部生效,磁盘零痕迹(历史残留升级后首次启动自动清理,你自装的内容绝不触碰)。
- **模型弹层里点「已配置供应商」不再整层关闭**(REQ-061)——此前点已配置的供应商行想改 KEY,弹层会直接消失,改 KEY 的入口永远进不去(表单「返回」同样误关)。根因是点击判定在界面同步刷新时误把层内点击当成了层外点击,已修复;弹层外空白处点击照常关闭。
- **会话页输入框按钮"点了没反应"根治**(REQ-056)——三个叠加原因一并修复:①接管容器层级低于对话滚动区,按钮**看得见点不着**(点击被透明滚动层吃掉);②窄窗口/审查面板打开时底部按钮行溢出输入框外,推理强度/发送被挤到不可点(现模型名截断省略、按钮行自动换行);③会话页丢失 alpha 焦点样式作用域,点击后残留上游橙色粗焦点圈(现样式随组件走,两页一致)。
- **推理强度不再有"选择模型后可用"的死状态**(REQ-056)——登录且代理可用时自动选中默认模型 **Claude Sonnet 4.6**(高级档;不覆盖你的手动选择、不写死到本地),推理强度点开即「默认/低/中/高」;模型不支持档位时点开如实说明原因,任何状态点击都有反馈。
- **自带 KEY(BYOK)供应商在新模型选择器里"消失"**(REQ-056)——未配置 KEY 的供应商此前被整行隐藏且无处补配;现在如实显示「需 KEY · 点击配置」直达配置表单,并补回「＋ 添加自定义节点/供应商」入口。注:正式包与本地测试包的数据目录相互独立,此前在测试包里填过的 KEY 需在正式包里重填一次。

## [0.1.2] - 2026-07-07

### Changed
- **输入框(composer)全面统一为 alpha 自建组件**(REQ-055)——此前首页与会话页是两套实现(首页自建、会话页为 opencode 原生加注入),反复出现行为不一致:首页推理强度点了没反应、模型按钮在无工作区时点击无反馈、agent 下拉泄漏内部专用档(alpha-automation 等)、点击后残留粗焦点圈。现在两处渲染**同一个组件、同一份样式**:模型/推理强度/agent/权限为本地选择、提交时作为显式参数发给引擎(不再遥控隐藏控件),推理强度即点即生效且跨页面一致;agent 列表只显示可用项(内部专用档彻底隐藏);会话页补齐上下文用量环;无工作区时所有控件引导先选工作区,不再有点了没反应的死按钮。诚实边界:附件/拖拽/图片粘贴暂未迁移(+ 菜单能力不变)。

### Fixed
- **首页模型/推理强度按钮死点**(REQ-054,随上条根除)——零工作区(全新安装首启/清除数据后)模型按钮点击无反应、推理强度对有档位模型切换不生效的问题,随 composer 统一重构从机制上消除。

## [0.1.1] - 2026-07-07

### Added
- **首次把项目派发到云端会先征得你同意**(B16 隐私合规,需下个签名版本生效)——每个项目**首次**使用云执行时,会弹窗说明将发送什么(本次的代码差异或任务文本)、发往哪里、可以拒绝,同意后按项目记录、不再重复询问;拒绝则不发送。配套:登录页明确告知"平台代付模式下对话内容会经平台处理"并提供自带密钥(BYOK)的替代方式,官网隐私政策补充了对话内容与云执行的数据处理专章(并修正了此前"不上传源代码"的不准确表述)。
- **技能市场的 Agent 也能远程上架安装了**(REQ-046,需下个签名版本生效)——此前只有连接器(MCP)和技能支持云端上架,Agent 必须随 app 打包;现在运营方在云端上架的 Agent,联网即见、点装即用(下载校验钉死,与技能同一安全管线)。自此**新增连接器/技能/Agent/插件都无需更新 app**:市场清单与内容统一由云端下发,app 内置清单只作断网兜底(发版时自动同步,不再手工维护)。
- **「数据 ▸ 清除数据…」**(C16,需下个签名版本生效)——app 内一键清除自己的数据,分两级:**仅凭证**(删除登录 token、BYOK 密钥、连接器密钥并登出,会话保留;删除范围逐项列出后确认);**全部数据**(为卸载做准备:应用数据、全局安装物 `~/.alpha` 及桥接链接、可勾选的引擎数据——会话数据库与独立 opencode CLI 共享,明示后由你决定;先提示导出会话数据库,红色终确认列出体积,清除后退出)。绝不触碰你的项目文件与 `~/.opencode` 里你自建的内容;逐项结果留痕日志。配套 [卸载与残留清单文档](UNINSTALL.md)(菜单内「卸载与数据残留说明」直达)。
- **技能市场补货三条技能 + 「设计套件」回归**(REQ-045;远程市场上架,联网即见,无需更新 app)——此前撤下的「MCP 构建指南 / 视觉海报设计 / 品牌规范应用」内容就绪,重新上架:内容再分发自 Anthropic 官方示例技能(Apache-2.0,来源与许可声明随内容一并下载,下载逐文件校验);「设计套件」随两个成员齐整回归,「开发套件」补回「MCP 构建指南」可选成员。注:「视觉海报设计」含设计字体约 5.4MB,安装时下载。
- **技能市场上架两个新连接器**(E2/E6;远程市场上架,联网即见,无需更新 app)——**钉钉**(官方发布的 dingtalk-mcp:通讯录/机器人消息/DING 等;详情页如实标注其源码不可公开审计的供应链警示)与**数据库(DBHub)**(Bytebase 官方:PostgreSQL/MySQL/SQLite 等只读查询;固定为仍支持只读开关的版本,连接串按密钥采集、不落明文)。钉钉同时并入「中国办公套件」。

- **扩展安装不再可能静默写进早已失效的临时目录**(REQ-047,需下个签名版本生效)——app 缓存「登录 shell 环境」时会把启动现场继承的内部控制变量(数据目录重定向、调试端口开关、迁移开关等)一并永久记住:此后每次启动(包括从 Finder 正常打开)都套用这些残留值,最坏时「安装成功」实际写进一个早已删除的临时目录(界面显示已装、实际不可用),且调试端口可能被常开。现在环境探测只捕获登录 shell 自己导出的内容(你在 .zshrc 里配置的 API key 等照常生效),已被污染的旧缓存会在启动时剥离危险项并留痕、随后自动重建干净。
- **「迁移旧安装」不再可能覆盖你自建的同名技能**(REQ-044,需下个签名版本生效)——定制中心的旧安装迁移此前只按名字匹配:如果你自己写过一个与市场条目同名的技能(真机上确实撞到过),「迁移」会用市场版把它覆盖并删除原件。现在迁移候选必须通过来源核验(与 app 打包资产逐字节一致才认定为 alpha 安装物),核验不过的一律不列入、绝不触碰,排除原因记录在日志;宁可漏迁需要你手动处理的项,也不动你的内容。
