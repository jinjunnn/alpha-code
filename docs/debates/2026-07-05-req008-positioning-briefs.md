## D1 团队协作:共享 workspace/会话,还是只「多个独立租户共享云」?

**现状**:POSITIONING〔待补〕+ NON_GOALS 用户群段未决;E13(团队协作多端 workspace 同步)因此 parked。

**事实基底**:会话真源 = 本地 SQLite(channel 后缀、单机);云平台(B)只有 run ledger(Redis)与 job 编排,**无任何会话/workspace 状态**;上游 opencode 无多用户原语。做共享 = 自建第二套同步引擎 + 权限模型 + 冲突解决,与「不重写 session 引擎」(NON_GOALS#2)与薄后端北极星正面冲突。

- **A(建议)不做**:定位钉死「多租户 = 多个独立租户共享云执行平台,无共享 workspace/会话」。E13 → rejected(激活条件:真实付费团队需求出现 **且** 上游出现多用户原语)。
- **B 轻量折中远期占位**:只共享「云 run 产物」(runId 链接给同事看结果,C 仓渲染),不动会话;不排期。
- **C 纳入 roadmap**:承担同步引擎成本。

## D2 企业租户(合同/SSO/合规)是否纳入?

**事实基底**:C 仓(注册/license/计费门户)与 B 仓(配额/计费校验)都按**个人订阅**形态在建;SSO/SCIM/合同/审计/数据驻留是另一条销售与合规战线,当前阶段(分发就绪)无承载面。

- **A(建议)不纳入**:NON_GOALS 明确写死;重评触发 = 出现真实付费企业线索,或 C 仓 license 体系成熟后主动重评。
- **B 远期占位**(定价页留企业位,不排期)。
- **C 纳入 roadmap**。

**后果差异**:A 则 B16 合规面维持「个人用户 PIPL」,不叠企业合规;官网/定价不留企业位。

## D3 用户下沉:是否服务「零配置非技术用户」?

**事实基底**:主画像 = power user。但「登录即代付」(platform-pays 代理,REQ-002 verified)已让不懂 BYOK 的人能用——**软下沉已经发生**。真正的零配置小白还差:引导式 onboarding、错误自解释全覆盖(B11 只做了一半)、防呆、面向小白的文档/支持面。

- **A(建议)不下沉**:画像维持 power user;「登录即用」记为既有事实(降低门槛),不升格为零配置目标;POSITIONING〔待补〕清除。
- **B 半下沉**:GOALS 立一条 onboarding 验收(下载→登录→能对话 ≤3 步),不承诺零配置。(注:deep-link 登录链已通,此条实际上接近达成。)
- **C 正式下沉**:连带 B11 全量 + 文档 + 支持面,当前成本高。
